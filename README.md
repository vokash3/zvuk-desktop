### Общее описание проекта (Project Overview)

Проект представляет собой **десктопное приложение, созданное с использованием Electron**. Его основная цель — создать специализированную обертку (wrapper) вокруг внешнего стримингового сервиса "Звук" (`zvuk.com`). Вместо того чтобы просто предоставлять ссылку на сайт, приложение упаковывает этот функционал в полноценный, кроссплатформенный десктопный клиент.

### 🛠️ Архитектура и компоненты (Architecture and Components)

Приложение имеет классическую архитектуру Electron с разделением ответственности между тремя процессами: главный процесс (Main), рендерер (Renderer) и предзагрузка (Preload).

1.  **`zvuk-desktop/main.js` (Главный процесс — Main Process):**
    *   Это "мозг" приложения, который взаимодействует напрямую с операционной системой (OS API).
    *   **Функции:** Управление жизненным циклом окна (`BrowserWindow`), создание системного трея и контекстного меню (`Tray`, `Menu`). Он отвечает за инициализацию самого приложения, обработку нажатия кнопок в трее ("Открыть Zvuk") и управление обновлениями.
    *   **Ключевая особенность:** Содержит сложную логику для обработки обновлений (`electron-updater`), что гарантирует, что приложение остается актуальным.

2.  **`zvuk-desktop/index.html` (Контейнер — Shell):**
    *   Это основная разметка, которая служит оболочкой для всего функционала. В ней размещается веб-представление (`<webview>`), которое фактически отображает контент Zvuk.

3.  **`zvuk-desktop/renderer.js` (Рендерер — UI Logic):**
    *   Этот скрипт обрабатывает события пользовательского интерфейса, относящиеся к навигации в рамках встроенного веб-представления (`webview`). Он прикрепляет обработчики к кнопкам "Назад" и "Вперед", позволяя пользователю перемещаться по контенту Zvuk внутри приложения.

4.  **`zvuk-desktop/preload.js` (Мост — Security Bridge):**
    *   Скрипт, который выполняется в специальной безопасной среде **до** загрузки основного контента. Его задача — безопасно "поднять мост" между уязвимым веб-контентом (renderer) и привилегированным кодом Node.js/Electron API (main process). В данном случае он минимален, но его присутствие критично для архитектуры безопасности Electron.

### ⚙️ Как это работает (Workflow Summary)

1.  **Запуск:** Пользователь запускает приложение через `npm start`.
2.  **Инициализация:** Запускается `main.js`, который создает окно и значок в системном трее.
3.  **Отображение:** В главном окне загружается `index.html`, внутри которого активируется `<webview>`, который отображает поток данных со стриминга.
4.  **Взаимодействие:** Когда пользователь нажимает кнопки "Назад"/"Вперед" в интерфейсе, срабатывает обработчик из `renderer.js`, который вызывает соответствующие методы у элемента `<webview>`.
5.  **Обновления и Обслуживание:** В фоновом режиме `main.js` постоянно следит за обновлениями (`autoUpdater`), уведомляя пользователя о необходимости установки новой версии.

# Ручная сборка

## Запуск

```bash
npm install
npm start
```

## Сборка (macOS .dmg)

```bash
npm run dist
```

## Решение проблем

### MacOS

Если приложение не запускается и просит отправить себя в корзину из-за "повреждения", нужно выполнить команду `xattr -c /Applications/Zvuk\ Desktop.app` в терминале, после чего запустить программу.
